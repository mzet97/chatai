# M2 — Fragmentação, embeddings reais, FTS5 e publicação consistente

Cobre RAG-04 (fragmentação/embeddings) e infra de RAG-05 (FTS5).
Recuperação híbrida e `RetrievalService` são M3.

## Decisões

- Tokenizer real do modelo preparado para chunking (`get_tokenizer_encode`,
  `local_files_only`); sem tokenizer heurístico paralelo.
- Alvo 320 / overlap ≤48 em **unidades inteiras** (parágrafo/seção/página);
  subdivisão por sentenças e, no patológico, janelas de tokens com overlap.
- `context_hint` (caminho de seção) só na representação de busca;
  texto citável puro em `Chunk.text`.
- Revisão fixada `614241f6` (`rag_prepare` grava `.revision`; `is_prepared`
  recusa diretório divergente). CPU baseline, singleton por processo,
  `trust_remote_code=False`.
- BLOB: `dim uint32 LE + float32 LE`, normalizado (pack recusa norma ≠1).
- FTS5 `unicode61` puro: o SQLite do projeto rejeita opções do tokenizer
  (`remove_diacritics` → parse error), então folding de acentos é app-side
  (`fold`, NFD−Mn) no índice e na consulta.
- Publicação atômica: FTS da versão nova + troca de `active_version` +
  adoção de `active_profile` na mesma transação curta; versão antiga sai do
  FTS mas mantém chunks (histórico para citações antigas — M4/M6).
- Perfis incompatíveis recusam publicação com erro acionável (reindexação).
