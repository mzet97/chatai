# RAG — estados, contratos e plano M1

## Estados
Job: `queued → extracting → chunking → embedding → publishing → ready`;
`failed | cancelled | needs_ocr` (terminais; retry cria nova tentativa).
Documento: `upload → processing → ready | partial | needs_ocr | failed`.
Versão: `staging` (provisória) → `active` (atômica) → `archived`.

## Contratos M1
- `POST /api/rag/bases` {name} → {uuid, name}; dono = sessão.
- `POST /api/rag/bases/<uuid>/documents` (multipart) → {doc_uuid,
  version, job_id, state: processing}. Sem "Pronto" antes do worker.
- Job adquirido por `UPDATE ... WHERE state='queued'` (atômico, sem
  select_for_update). Lease 5 min + heartbeat; worker atrasado nunca
  publica versão cancelada/excluída (checa geração na publicação).
- Extração retorna {text, locators, pages/coverage, warnings[]}.
  Localizador: PDF `p<pg>`; DOCX `s<sec>/p<par>` ou `t<tbl>r<row>`;
  TXT/MD `l<ini>-<fim>` + seção por títulos `#`.

## Limites M1 (aplicados)
20 MiB/arquivo; 300 págs/PDF; 5.000 frag/doc (M2); 50.000/usuário;
timeout extração 120s; expansão texto ≤4× bytes originais.
