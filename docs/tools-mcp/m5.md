# M5 — Seleção por conversa, atividade/inspeção, ambos os modos (incremento SDD)

## Decisões (ADR-T4)
- `ConversationToolPrefs`: 1:1 com Conversation; `enabled: [stable_id]` (default
  `[]` = sem ferramentas = sem MCP, sem `create` com tools). Interseção por
  execução: prefs ∩ admin/habilitadas ∩ concedidas ao usuário ∩ catálogo atual.
- Caminho com ferramentas em `execute_run`: etapas `messages.create` (não-stream
  por etapa, como o loop M1) + eventos SSE de ciclo de vida nos dois modos.
  Sem streaming fino de `input_json_delta`: nunca executamos de JSON parcial
  por construção (etapa completa → parse → valida → autoriza → executa).
  Modo streaming emite `text_delta` por etapa; modo completo retém texto até `done`.
- Pausa: `awaiting_approval` no run + `run_paused` + fim do segmento HTTP.
  `POST continue` retoma do estado persistido (revalida prefs/política/schema/
  aprovação), sem re-perguntar ao modelo.
- Painel didático = `run_detail` estendido (etapas, invocações, aprovações —
  sem segredos, sem dumps brutos).

## Eventos SSE novos (envelope run_id+seq existente)
`model_step_started{step}` → `tool_call_requested{step,tool_use_id,name}` →
`tool_approval_required{step,tool_use_id,name,approval_id}` |
`tool_started{step,tool_use_id,name}` → `tool_finished{step,tool_use_id,ok}` →
`run_paused{state:awaiting_approval}`. `done` só no turno inteiro.

## Endpoints novos
- `GET/PUT /api/conversations/<uuid>/tools` — prefs (lista de stable_ids).
- `POST /api/runs/<uuid>/approvals/<id>/decide` — approve/deny (CSRF,
  idempotency_key).
- `POST /api/runs/<uuid>/continue` — retoma execução pausada.
- `GET /api/conversations/<uuid>/tools/catalog` — autorizadas p/ seleção na UI.
